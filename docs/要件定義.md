# FlatScan Web 要件定義書・技術仕様書

# 1. プロジェクト概要

## 1.1 プロジェクト名

FlatScan Web

## 1.2 目的

FlatScan Webは、スマートフォンおよびPCのWebブラウザから、
書籍・書類・ノート・印刷物を高品質にデジタル化する
個人専用ドキュメントスキャナーである。

vFlat Scanに相当する機能と使い勝手を目標とし、
以下の処理を一連の操作で実行できることを目的とする。

1. カメラ撮影・画像取り込み
2. ページ領域の自動検出
3. 台形・傾き・曲面補正
4. 見開きページの分割
5. 影・照明ムラの補正
6. 指の検出・除去
7. OCRによる文字認識
8. ページの編集・管理
9. 検索可能PDF等への出力
10. プロジェクトの保存・再開

## 1.3 基本方針

- 個人利用に特化する。
- ユーザー登録・ログインを必要としない。
- スマートフォンとPCの両方で利用できる。
- ブラウザから直接利用できる。
- 基本機能は可能な限りオフラインで動作する。
- AI処理はローカル・サーバーの両方式を提供する。
- サーバー処理は利用者の明示的な許可を必要とする。
- プロジェクトデータはブラウザ内に保存する。
- クラウドへの永続保存・同期は行わない。
- 元画像を保持し、非破壊編集を基本とする。
- AIによる文書内容の誤改変を防止する。
- AIモデルは交換可能な構成とする。

## 1.4 対象ユーザー

本アプリケーションの利用者は開発者本人を想定する。

複数ユーザー管理、共同編集、課金、
組織向け権限管理は対象外とする。

## 1.5 対応環境

### PC
- Windows 11
- サポート対象のmacOS

### スマートフォン・タブレット
- iOS
- iPadOS
- Android

### ブラウザ
- Google Chrome
- Microsoft Edge
- Safari
- Firefox

原則として現行版と直前の主要版を対象とする。

ただし、AI推論機能についてはブラウザごとの
対応状況を検証し、非対応環境では代替方式を提供する。

## 1.6 対象外

以下はv1.0の対象外とする。

- ユーザーアカウント管理
- クラウド同期
- クラウドバックアップ
- 複数ユーザーによる共同編集
- 課金・広告
- 文書の自動翻訳
- 文書の自動要約
- 電子署名
- 手書き文字の高精度認識保証
- AIによる隠れた文字の正確な復元保証

## 2.2 処理の基本原則

画像処理機能とUIを分離する。

各画像処理機能は共通の処理インターフェースを持ち、
ローカルAIとサーバーAIを切り替え可能とする。

AIモデルの変更によって、ページ管理や
画面コンポーネントの大規模変更が発生しない構造とする。

## 2.3 AI処理モード

### ローカルモード

- ブラウザ内で画像処理を実行する。
- 画像を外部サーバーへ送信しない。
- オフライン利用を目標とする。
- 端末性能に応じて処理品質・解像度を調整できる。
- 対応しないモデルについては理由を表示する。

### サーバーモード

- 利用者が明示的に選択した場合のみ使用する。
- 処理に必要な画像だけを一時送信する。
- サーバー側で画像を永続保存しない。
- 処理結果をブラウザに返却する。
- 処理終了後、一時データを削除する。
- エラー・タイムアウト時も削除処理を行う。
- 画像・OCR内容をログへ記録しない。

### 共通ルール

- 初期設定はローカルモードとする。
- 処理単位でモードを変更できる。
- サーバーへの自動フォールバックは禁止する。
- ローカル処理失敗時は利用者に選択を求める。
- 処理方式によらず元画像を保持する。
- 両方式の処理結果が完全一致することは要求しない。
- 両方式とも共通の最低品質基準を満たすことを目標とする。

## 3.3 ローカルAI

採用技術：
- ONNX Runtime Web
- WebAssembly
- WebGPU（対応環境のみ）

推論優先順位：
1. WebGPU
2. WebAssembly
3. 利用者にサーバー処理を提案

WebGPU非対応環境ではWebAssemblyを試行する。

ただし、モデルの演算子互換性・メモリ要件を確認し、
実行不可能な場合は適切なエラーを表示する。

## 3.4 曲面補正AI

候補モデル：
- UVDoc
- DocTr

評価項目：
- 書籍の綴じ目付近の補正精度
- 日本語縦書きへの影響
- 文字の変形・欠落
- 図表の保持
- 処理速度
- メモリ使用量
- ONNX変換可能性
- ブラウザ互換性
- ライセンス条件

採用条件：
- 標準評価画像で品質基準を満たす。
- サーバー推論が安定動作する。
- ローカル推論について対応環境を明示できる。
- 利用条件・ライセンスに問題がない。

ローカル実行可能なモデルが存在しない場合は、
軽量モデルの追加学習・蒸留・最適化を検討する。

モデル名は実証試験後に確定する。

## 3.5 指検出・画像修復AI

### 指検出

方式：
- セグメンテーションモデル

要件：
- 紙面に重なった指の領域を検出する。
- 指の輪郭をマスクとして取得する。
- マスクを手動修正できる。
- 誤検出を解除できる。

一般的な手検出モデルでは精度不足となる場合、
専用モデルの追加学習を検討する。

### 指除去

候補：
- LaMa系Inpaintingモデル

要件：
- 指領域を自然に修復する。
- 既存の文字・図表を可能な限り保持する。
- 修復前後を比較できる。
- 修復結果を採用・破棄できる。
- 修復箇所を可視化できる。

文字を隠している指については、
原文の正確な復元を保証しない。

文字領域の修復は警告対象とする。

## 3.6 OCR

### ローカルOCR

第一候補：
- Tesseract.js

対象：
- 日本語横書き
- 日本語縦書き
- 英語
- 日本語・英語混在

縦書きについては専用モデルや
前処理の必要性を検証する。

### サーバーOCR

第一候補：
- PaddleOCR系

代替：
- Tesseract OCR

### OCR選定基準

- 日本語文字認識精度
- 縦書き認識精度
- ルビの取り扱い
- 段組みの読み順
- 表・図表の認識
- 文字位置情報の取得
- 処理時間
- メモリ使用量
- ライセンス

# 5. 非機能要件

## 5.1 性能

性能基準は標準テスト画像を使用して測定する。

標準画像：
- 長辺約3,000px
- 約12MPの撮影画像を想定
- JPEG形式を基本とする

性能目標：

NFR-001 画面操作応答：0.2秒以内
NFR-002 ページ検出：3秒以内
NFR-003 通常画像補正：5秒以内
NFR-004 AI曲面補正：15秒以内
NFR-005 AI指除去：20秒以内
NFR-006 OCR：1ページ15秒以内
NFR-007 PDF生成：50ページ60秒以内
NFR-008 100ページのプロジェクトを管理可能
NFR-009 長時間処理中も進捗表示する
NFR-010 長時間処理を中止できる

測定方法：
- 基準端末を指定する。
- ローカル・サーバー処理を別々に測定する。
- 原則として90パーセンタイルで評価する。
- 初回モデル読み込み時間は別途測定する。

基準端末・ネットワーク条件は性能試験前に確定する。

## 5.2 セキュリティ

NFR-011 HTTPSを使用する。
NFR-012 カメラアクセスはブラウザの許可に従う。
NFR-013 外部AI送信は明示操作を必要とする。
NFR-014 サーバー側の画像永続保存を禁止する。

# 12. リスク管理

R-001 ローカルAIの処理負荷が高い。
対策：軽量モデル、解像度調整、サーバー選択。

R-002 曲面補正の精度が不足する。
対策：複数モデル比較、追加学習、手動補正。

R-003 指除去で文字が破損する。
対策：文字領域警告、元画像保持、承認操作。

R-004 縦書きOCRの精度が不足する。
対策：専用モデル、前処理、サーバーOCR。

R-005 ブラウザ保存データが消失する。
対策：自動保存、バックアップ、容量警告。

R-006 Safariで一部AIが動作しない。
対策：WebAssembly、モデル最適化、サーバー処理。

R-007 サーバー処理で情報漏えいする。
対策：HTTPS、アクセス制御、ログ除外、データ削除。

R-008 PDF内の日本語文字配置が崩れる。
対策：フォント埋め込み、座標検証、代替PDFエンジン。

R-009 AIモデルのライセンスが不適合。
対策：採用前にコード・重み・依存物の条件を確認。

R-010 画像処理中にメモリ不足となる。
対策：ページ単位処理、解像度制御、メモリ解放。
